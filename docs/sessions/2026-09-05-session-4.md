# Session 4 — evidence, and the discipline to keep it true

Published the corpus run, made it reproducible and CI-enforced, added a merge
gate, and brought the backlog up to the same standard.

The theme: Plumbline had done the work to be trustworthy and had no way to show
it. The v0.1.0 corpus run existed only as prose in [`b904e11`][b904e11]'s commit
message, and could not be reproduced even internally because nothing was pinned.

## What was verified, and how

| Claim | Result | How |
| --- | --- | --- |
| v0.1.0's "13 missing-auth errors, all genuine" | **Reproduces exactly** | Re-linted both public repos at pinned revisions, three weeks later |
| soroban-examples: 78 files / 9 err / 85 warn | 79 / 9 / 86 | One file added upstream, carrying one warning |
| stellar-contracts: 240 / 4 / 19 | Identical | — |
| The 174-findings total and per-class counts (44/6/2/5) | **Not reproducible** | No commit was pinned when measured; quoted and cited, never re-asserted |
| The four private working workspaces | **Unrecoverable** | Unnamed in git history. Nobody can reproduce that row |

Findings classified by hand: all 13 `missing-auth` (12 genuine, 1 the rule
cannot decide — a vote gated by a Merkle proof), all 31 `unchecked-arithmetic`
(30 genuine, **1 false positive**). `panic-in-contract`'s 74 were sampled, not
individually classified, and [corpus-run.md](../corpus-run.md) says so rather
than implying precision it did not measure.

## What the corpus run found immediately

**`contractmeta-missing` fires on 96% of the corpus** — 91 findings across 95
contract-declaring files; exactly one contract in 319 uses `contractmeta!`.

Every finding is factually correct, so it is not a false positive. The problem is
the rate, against this project's own standard that a rule earns its noise or does
not ship. It passed CI, its own fixtures, and code review; only real contracts
showed it. No decision was taken — [#31](https://github.com/use-plumbline/plumbline/issues/31)
holds it with the numbers attached.

That is the argument for the whole session in one example.

## Decisions

**The corpus is pinned by commit, so the counts are deterministic.** This turned
out to matter more than expected: it means a baseline diff is a *precise* signal.
`corpus/baseline.txt` plus `make corpus-check` makes "this branch changed what
Plumbline says about 319 files of real contracts" a red check. Had it existed in
August, `contractmeta-missing` would have arrived at PR #27 as a `+91` diff.

**The corpus check does not assert "it completed".** That was the original plan
and it was too weak. Pinning made the stronger check available, and the failure
message asks for reasoning rather than just blocking.

**Maintainer-owned excludes `rules/` and `testdata/`.** Blast radius, not
gatekeeping: a mistake in one rule is one wrong finding caught by its own
fixtures; a mistake in the engine or the parser boundary is silently wrong
findings across every rule at once. Gating `rules/` would also block the exact
contribution this project is shaped to accept. The same list appears in the gate
regex, the PR template and CONTRIBUTING, and they move together.

**Wayfare's 7th gate was deliberately not ported.** Its scope-vs-linked-issue
check answers a question Wayfare needs for its money-correctness framing;
Plumbline's path gate covers the equivalent risk without a second mechanism.

**The gate lives in a script, not inline YAML.** Inline, it had neither static
analysis nor a test — for 200 lines of bash that decides whether to merge
somebody's code. Extracted, it gets both.

## Things that went wrong

- **CI on `main` had been red for three weeks**, since #27 merged on 2026-08-17,
  across three pushes. The failure belonged to none of them: `TestJSONOutput`
  asserted on `doc.Findings[0]`, which only ever worked because `missing-auth`
  happened to report the earliest line in the fixture. `contractmeta-missing`
  started reporting line 15 and element zero stopped being the finding the test
  was about. Fixed in `0f24bca`. It is also the concrete argument for the gate:
  three PRs were merged into a red main.
- **A comment line beginning `# shellcheck`** made shellcheck refuse to parse
  `merge-gate.sh` at all — it reads that as a malformed directive. Caught only
  because a real shellcheck binary was fetched rather than trusting CI to find
  it later.
- **`gh api --jq` does not accept `--arg`.** The first draft of the gate's
  self-exclusion used it. Replaced with an `awk` filter, which is also more
  legible than burying the exclusion inside a jq expression.

## Open

- **Why #28 was reverted is unknown.** The revert body is only "Reverts #28".
  [#2](https://github.com/use-plumbline/plumbline/issues/2) is annotated with
  what is verifiable and explicitly does not guess. A maintainer should say
  before it is re-attempted; the reason changes the work.
- **`main` has no branch protection.** CI and the merge gate are both advisory:
  a direct push bypasses everything, which is how three PRs landed on a red
  main. Enabling required status checks is the natural completion of this work
  and was left as a deliberate decision rather than imposed, since it changes
  how the maintainer's own pushes behave.
- **The corpus is reference material only.** Both repositories are written to be
  exemplary. [#32](https://github.com/use-plumbline/plumbline/issues/32) tracks
  adding a production codebase; `CometDEX/comet-contracts-v1` is verified as a
  candidate, and its math sits outside `#[contractimpl]`, which would put a
  number on the entry-point-only limitation.
- **[#33](https://github.com/use-plumbline/plumbline/issues/33)** is the one
  measured false positive: a `u32` accumulator in `soroban-examples/alloc`
  reported as token arithmetic.
