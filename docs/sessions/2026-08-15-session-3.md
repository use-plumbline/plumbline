## The false-positive pass

Run over third-party Soroban source, Plumbline reported **174** findings. Four
of them were classes of the linter being wrong about correct code.

| Class | Findings | Fix |
| --- | --- | --- |
| Mock contracts in test sources | 44 | Skip `test.rs`, `tests.rs`, `tests/`, `test/`, and `#[cfg(test)]` modules |
| OpenZeppelin `#[only_*]` macros | 6 | Treat the four authorizing macros as auth |
| One-shot initializers | 2 | Exempt `if storage.has(&k) { return/panic }` |
| Ledger arithmetic read as token arithmetic | 5 | Resolve `sequence`/`timestamp`/`protocol_version`/`len` as narrow |

After: soroban-examples 78 files / 9 errors / 85 warnings; OpenZeppelin
stellar-contracts 240 files / 4 errors / 19 warnings; four working workspaces
66 files / 0 errors / 7 warnings, two of them completely clean.

Every remaining error was read. They are teaching examples whose entry points
genuinely take no authorization, plus one entry point authorized by a Merkle
proof — a case the rule cannot distinguish from an unprotected one, now
documented as a limitation rather than papered over.

## Decisions

**Configuration cannot change what a rule looks for.** Severity, enablement and
file selection are policy and live in `internal/config`. What counts as a
finding stays in the rule. The engine already had the severity and disable
seams from session 1; this added the file-selection seam beside them.

**Config knows about the engine, not the other way round.** `Config.Apply(*engine.Engine)`.
Rules and rule execution have no opinion about where their settings came from.

**An unrecognised rule ID in `[rules]` is an error.** A misspelt key looks
exactly like a rule that was switched off successfully. The cost of the strict
choice is that a config naming a newer rule fails on an older Plumbline; the
error names the rule and points at `--list-rules`.

**The one-shot-initializer exemption is deliberately over-broad.** It matches
`if storage.has(&k) { bail }` anywhere in the body, which also covers one-shot
*claim* patterns, so a function that guards a one-shot key and separately needs
authorization is not reported. The guard is the dominant idiom in contracts
written before constructors existed, and reporting it fired on most of the
ecosystem. Recorded in the release notes as a known false negative.

**`unchecked-arithmetic` still reports what it cannot type.** `i128` amounts
usually arrive through a helper call whose return type Plumbline cannot see, so
narrowing to *known* 128-bit operands would drop most of the true positives on
`liquidity_pool`. The SDK accessors were the surgical fix: one resolved operand
resolves the expression, so `sequence() / config.epoch_length` becomes narrow
without the rule getting quieter about money.

**JSON carries its own `schemaVersion`, not Plumbline's version.** The two move
for different reasons. A tool parsing the output cares about field names, not
about which rules shipped that week.

**BurntSushi/toml, not a hand-rolled parser.** The schema is two keys, but a
hand-rolled parser rejects valid TOML in ways that become the user's problem to
debug, and strict decoding is what makes an unknown key an error.

## The release

`v0.1.0` tagged and released. Release notes lead with what the rules catch,
then what they do not, then a per-rule list of known blind spots in both
directions, then the corpus the claims were verified against.

Verified by tag from outside the repository —
`Fury03/plumbline-tag-check`, private — which asserts the root
`.plumbline.toml` is picked up, the `config` input overrides it, findings fail
the build at the default threshold, JSON parses, and a mistyped path exits 2.
All green.

## Open

- **`setup-go` cannot cache for external callers.** `cache-dependency-path`
  resolves to an absolute path inside `_actions/`, outside the caller's
  workspace, so every external run logs `Restore cache failed` and re-downloads
  modules. Not a failure — the run is green — but it costs time on every run.
  The fix is a trade: `cache: false` removes the warning and the wasted
  restore, and also gives up the caching that does work when Plumbline
  dogfoods its own action with `uses: ./`.
- SARIF output, so findings land in GitHub's security tab.
- `panic-in-contract` only scans entry-point bodies; following helper calls the
  way `missing-auth` does would widen it.
